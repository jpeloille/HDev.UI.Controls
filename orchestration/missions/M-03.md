# M-03 : diagnostic de QX-02, les popups ne survivent pas à une désactivation

Ouverte le 05/10/2026. **Constat de Julien** sur le bureau réel, avec la démo de `suite-M-01` : les popups ne restent pas ouverts quand la fenêtre perd brièvement le focus.

**L'attendu** (Plan-Editeurs, E0 et E2) : un popup ouvert survit à une brève désactivation de la fenêtre, grâce à une garde débouncée, et se ferme sur un vrai clic extérieur. Depuis E2, il n'y a plus qu'une seule garde pour toute la suite : `HDevPopupDismissGuard`, utilisée par le socle, la ComboBox et les menus.

## Objet

C'est une mission de **diagnostic, pas de correction**. Il s'agit de :
- reproduire le défaut ;
- dire si E2 l'a introduit ou s'il existait déjà ;
- trouver la cause ;
- proposer un correctif.

Le correctif est décidé ensuite par l'orchestratrice, avec Julien, puis appliqué dans M-01, puisque la garde unique appartient à E2.

## Protocole sur le bureau

L'environnement : GNOME sous Wayland, et la démo tourne sous XWayland (`DISPLAY=:0`, `X11PlatformOptions.OverlayPopups`).

Les popups à tester :
- le calendrier de HDevDateEdit ;
- la liste de HDevComboBox ;
- un menu (HDevMenuPopup) ;
- HDevLookUpEdit ;
- HDevDropDownEdit (après E2 seulement), s'il est dans la démo.

Les scénarios, pour chaque popup et chaque état :
1. une brève désactivation par Alt+Tab aller-retour ;
2. le focus pris par une autre fenêtre puis rendu, par exemple avec `xdotool windowactivate` sur une autre fenêtre X ;
3. un vrai clic extérieur, dans la fenêtre, hors du popup ;
4. un clic hors de la fenêtre.

L'attendu : rester ouvert pour 1 et 2, se fermer pour 3 et 4.

**Preuves.** Une capture d'écran avant et après chaque scénario significatif, rangée dans `RiderProjects/atelier/missions/M-03/captures/` (hors dépôt).
